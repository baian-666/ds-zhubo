# 导演主持指导与收尾交棒

2026-10-17。对应[桌面模拟](PACING-REHEARSAL-2026-10-17.md)中“说等观众，却安排短暂停顿续讲”的问题。

2026-10-18更新：默认持续主持下，0或无计划进入30秒静默观察；缺失closing改为有上限的延迟重试，不沿用开头草案。12轮/10分钟不再是默认结束条件。下文是原实现和历史验证，当前规则见[持续主持修复](HOSTING-CONTINUITY-2026-10-18.md)。

## 原因与处理

先前流式 decision 在首句前确定节奏，后续台词可能转为邀请观众，开头的继续计划却仍然生效。同时 withoutInputMs 包含角色自己的发言时间，不能表示已经等观众多久。模型的主持判断也有不稳定之处，不能单靠换一段提示词就宣称自然度已解决。

本次给现有模型增加主持指导和正反例，没有训练新模型，也没有增加另一位模型在每轮前指导。内容见 [hosting-closing.mjs](../apps/cohost/hosting-closing.mjs)：

- 连贯讲完整观点、例子；句号不等于交棒，反问后自己解释也不必等观众。
- 真正邀请观众后兑现留白，不再追加自己的案例或抢答。
- 搭档要讲完时倾听，观众起哄不能撤销人工控制。
- 按实际交棒后的时长理解沉默，刚等几秒不说“半天没人理”。
- 接受“讲短点、展开些、让我说”等反馈，调整真实节奏，不只口头答应。

## 实现边界

自主安排的流式 reply_* 在台词结束后提交一个 closing：

| handoff | 含义 | 再观察时间 |
| --- | --- | --- |
| continue | 继续展开同一话题 | 1～10秒 |
| audience | 真正向观众交棒 | 0只等新输入，或15～120秒 |
| listen | 留给搭档或结束主动发言 | 0，只等新输入 |

观众模式的最短等待是执行已承诺的交棒，不用于每个句号；新弹幕随时可带来新判断，不必耗完等待时间。示例推荐20～40秒，具体由模型选择，不是固定节目规则。

- 首句仍先返回；closing 属于同一次流式调用，不能更改 action、对象、发言内容或权限。没有新增首句前的串行请求。
- 只有供应商正常完成、closing合法且没有后续speech/重复closing，才能确认收尾计划。缺失/非法计划不截断有效台词；播完后暂停自主安排，界面沿用“模型判断未完成，点继续可重试”，不假称是模型主动等待。
- 初始 decision 的节奏为草案。执行时使用实际交付那一轮的最终计划；在音频真正播完、且没有更新输入时才应用。
- 新输入、正在讲话、人工暂停/叫停、静音、舞台断线和不完整交付仍可取消计划。纯wait/react保留原低频观察规则。
- audienceWaitMs 从实际交棒的播放完成时刻算起；新输入或人工控制使它失效。角色讲话时间不计入等待，无关的声音试听也不重置它。
- 保留原无人输入预算、单话轮播放、800字/10条流式记录上限。Live2D、语气、TTS分段与打断执行链不变。
