### Index 本地音色与表达参考

Index 的本机参考配置在 `data/indextts/reference.json`。`audio` 是音色参考；可选 `emotion.audio` 是独立的情绪参考，`emotion.alpha` 为 0–1 的混合参数；`name` 用于工作器健康信息。未提供 `emotion` 时保持旧行为，沿用音色参考的表达。工作器启动时读取一次，明确指定其他音色文件时不会套用不匹配的配置。

用户选定宵宫中文参考，持久素材放在 `data/indextts/voices/yoimiya-zh/`，`emotion.alpha=0.6` 保留第四版开心表达。随后已启用 `contextualEmotion:true`：默认改为自然平常，只有模型选择 happy 时才使用这段独立开心参考。首次固定语气切换记录在 `data/indextts/yoimiya-production-20261015/`，自动语气部署及备份在 `data/indextts/context-emotion-20261015/`。

每轮回复的 `speechStyle` 仅允许 neutral、happy、surprised、gentle。自动参与在原有 participate 决策中同时选择；人工回复在同一次流式生成的开头给出隐藏 `<voice:...>`，程序在进入字幕、历史和TTS前移除。整轮保持一种语气，已开始的台词不接受迟到标签改写。缺失/非法值回退neutral；不是关键词规则，不额外请求LLM。服务端从当前话轮取语气，忽略播放端传来的风格覆盖；取消、过期及声音修订号约束继续生效。其他TTS引擎保持原行为。

Index 每个请求独立应用预设：happy沿用独立开心参考0.60；neutral用calm向量0.45，gentle用calm 0.65，surprised用surprised 0.25，不带独立开心参考。向量预设是第一批克制参数，不能把gentle标签当成已通过主观听审的安慰效果。音色参考、语速、beams和CFM步数保持不变，不训练模型。关闭 `contextualEmotion` 并重启Index即可回到固定参考表达。

以后更换音色只需另存一段 1–15 秒的干净单人参考音频，备份并更新 `audio`，在没有收音、播放或合成时重启 Index 工作器。独立情绪参考可以保留，也可以替换/移除；每次先试听一条检查适配效果，不必重新训练模型或更改人设。现有 AIRI 发声页可以选择语音服务，但尚无本地参考音频上传/管理界面。工作器读取的新配置在启动后持续生效，下次自动启动也会沿用；不会自动热更新运行中的模型参考。

## 开始试播

1. 在项目目录双击 `启动小鲸鱼.cmd`，打开桌面 AIRI 直播侧栏。
2. 戴耳机，确认默认麦克风是要使用的设备。
3. 侧栏自动使用当前舞台的 AIRI 云端语音，两端只有一个收音和发声。
4. 等“开始收音”可用后点击。首次加载 VAD 可以多等一会。
5. 等状态显示“正在收音”，说一句话并停顿。音量条显示实际输入，下方依次显示检测到讲话、正在识别。最终文字和回复进入右侧聊天。
6. 小鲸鱼自动决定接话并解释理由。人工对照移到 [开发入口](http://127.0.0.1:8787/?debug)。
7. “停一下”停止当前回复、合成和播放。“停止收音”同时释放麦克风。收起聊天不会主动停收音。

首次可以说：“小鲸鱼，你觉得今天这个故事怎么样？”
若名字识别错误，或没有明显交棒证据，导演可以等待。可查看中间气泡的公开理由。
完整耗时仍在服务端时间线和开发入口中，识别、生成与播放回执不是同一指标。

首次使用必须允许桌面 AIRI 舞台访问麦克风。
服务不会自行开麦。启动失败或断线会停收音，需要再次手动开启。单段识别请求失败会明确提示，麦克风继续收音。
默认声音为 CosyVoice2 的 claire。自定义音色按用户决定后置。

直播跟随系统默认麦克风，实际设备名称在“当前配置”中显示。说话时音量条几乎不动，先检查 Windows 默认输入与输入音量。音量条有明显变化却一直等你说话，属于讲话检测阶段；显示正在识别则已进入识别阶段。
短暂停顿后继续说话，不再取消前一段识别。未返回的分段按原顺序合并后交给导演；识别按序执行，最多保留八个未完成分段，停止/断联仍取消并丢弃旧结果。650 ms 切句与原讲话检测阈值保持。
“调用或结果解析出错”表示执行失败；正常等待显示导演的公开理由。两种情况分别展示。

## 2026-10-16：组合叫停优先处理

真实记录核对：18:23:24第一句已转写，25.183至26.110的模型任务完成但没有执行stop；第二句34.840确认，36.905选择reply_host，替换旧回答时才取消。旧规则仅识别少数整句，两种组合说法均漏过。第一轮原始模型选择未保留，不能断言具体忽略分支，也不能采信角色自己生成的“第一下就停止了”。原始诊断保存在data/interrupt-diagnosis-20261016.json。

修复后，确定性的主播叫停规则接受有限个停止指令的重复/组合和可选称呼，包括用户的两句原话。整个文本必须只含这些指令和分隔符，引用、否定、假设、讨论和未确认的转写草稿不会直接触发停止。叫停同时取消候选和当前输出、消费本句话，并保持stop状态；新主播话到来才恢复正常判断。空闲时叫停也不再引出“停了停了”的回复。模型提示明确叫停优先于接梗，stop结果到达时即使旧回答已结束也保留安静状态。

取消记录interruptionReason与timings.cancelRequestedAt：host_stop为叫停，host_takeover为接管，reply_replaced为新回复替换，manual_interrupt为按钮打断。时间是服务端发出取消的时间，不是扬声器物理停声时间。客户端沿用原话轮失效与播放清理链路，不更改语音引擎、音色、情绪或断句。
