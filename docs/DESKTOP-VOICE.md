# 本机桌面与语音试播

更新：2026-10-11。这是 Windows 本机试播版本。还没有接真实平台弹幕，也没有完成真人自然话轮验收。

## 配置新语音账号

已有硅基流动 API 密钥时，先执行 ./scripts/local.ps1 configure:voice，打开 http://127.0.0.1:8789/ 。在本机页面粘贴密钥并点“保存并检查连接”。输入隐藏，不回显密钥、不保存浏览器缓存；检查账号模型列表后只更新忽略 .env 中的 SILICONFLOW_API_KEY，其他配置保留。

配置页 15 分钟有效，保存成功后自动关闭。它没有调用识别或合成接口，账号连接成功不等于模型权限、余额、实际语音质量或 AIRI 原生桥接已通过。目前直播间收音仍使用 Windows 备用链路。

## 直接使用

1. 打开桌面的 ds-zhubo 控制台，或 http://127.0.0.1:8787 。
2. 戴耳机，确认 Windows 默认麦克风是你要用的设备。
3. 在右侧点击“开始收音”，等状态显示“收音中”。
4. 说一句话并稍作停顿。正在识别的文字显示在右侧，确认后的文字进入中间聊天。
5. 小鲸鱼按当前导演模式决定等待或接话。自动模式更适合试播。
6. 勾选“小鲸鱼用系统声音回答”时，回复生成后由 Windows 中文声音朗读。开始收音前选择。
7. “让小鲸鱼停一下”停止当前回复和朗读。“停止收音”释放麦克风，停止本次语音话轮。

识别置信度低时，页面显示“这句识别不确定”。点击“检查这句识别文字”，确认或改正后发送。
不确定文字不会自动作为主播最终发言送给模型。
只想先测听懂与接话时机，可以在开始前关闭系统声音。

模型密钥仍只在本机忽略的 .env。无需在 AIRI 中再填 DeepSeek 密钥。
语音识别和系统发声在本机进行，没有向语音服务上传原始音频，也不保存麦克风录音。
识别后的主播文字会作为本场上下文发送给已配置的 DeepSeek。

## 启动与停止

在仓库目录的 PowerShell 中，用三个终端分别启动：

~~~powershell
./scripts/local.ps1 dev
./scripts/local.ps1 dev:airi
./scripts/local.ps1 dev:desktop
~~~

第一次安装桌面依赖：

~~~powershell
./scripts/local.ps1 setup:desktop
~~~

桌面配置保存在忽略的 data/desktop-profile，独立于已有 AIRI 配置。
桌面有一个 AIRI 形象窗口和一个直播控制台窗口。
控制台中仍保留网页舞台，桌面形象同时接收同一场次的表演指令。
桌面开发启动器默认连接 127.0.0.1:8787。启动 cohost 后再开桌面端。
开发期还需要网页舞台服务供控制台 iframe 使用。
脚本不会重置 vendor/airi 的已有修改。

后台启动的本次服务带 PID 文件，可用 scripts/stop-local.ps1 停止。
停止脚本先校验可执行文件和入口，不能拿旧 PID 停止其他程序。

## 实现与限制

- 本机适配器通过 Windows System.Speech 的中文听写和系统发声工作。不是浏览器的云端 SpeechRecognition。
- 语音活动与最终文本进入现有导演。普通发声不直接打断助播。准确识别到“等一下”等明确指令可以触发现有停止规则。
- 识别分段采用 650 ms / 1000 ms 静音阈值。它不能保证区分换气、思考和真正说完。
- 识别中间文本只作观察。低于 0.25 的最终置信度留给用户检查。
- 中文听写准确率是当前明显限制：系统生成的中文音频测试中，直播间和小鲸鱼出现错字，置信度约 0.20–0.22。不能把链路通过等同为识别质量通过。
- 目前等整段模型文字生成完成后开始系统朗读。首字耗时不等于开始出声耗时；后续可以做分句合成。
- 播放开始、保守已播文字前缀、完成与取消接入 scheduler。打断时只保留已确认播出的前缀。
- 必须戴耳机做同时听说测试。此版本没有独立的回声消除；外放可能被识别成主播。
- 系统声音还没有接 AIRI 的音频口型。现有姿态表演可运行，但不能称为逐音节口型同步。
- 一个页面拥有收音会话。其他页面不能抢走语音回复；页面失联约 8 秒停止收音。
- 麦克风启动失败、识别进程退出或停止收音会释放主播讲话状态。不会在后台自动重新开启麦克风。
- 大肥鱼模型尚未收到，使用默认形象。没有新增角色专属表情动画。

## 验证

~~~powershell
./scripts/local.ps1 check
./scripts/local.ps1 test
./scripts/local.ps1 check:desktop
~~~

scripts/voice-native-smoke.mjs 用本机系统声音生成音频文件，再交给真实离线识别引擎。
它也检查真实系统合成的进度与完成事件，合成回归输出到空设备，不证明扬声器已被人听到。
scripts/browser-voice-smoke.mjs 用模拟设备事件验证页面、导演、朗读和打断。
scripts/desktop-smoke.mjs 连接开发用 Electron 调试端口 9250，验证默认模型动作和恢复。
浏览器脚本可用 PLAYWRIGHT_MODULE 指向已有 Playwright。
默认启动不开放调试端口。验收时显式设置 APP_REMOTE_DEBUG=true、APP_REMOTE_DEBUG_PORT=9250。

已实现、设备注入测试、真实离线音频识别和真人试播必须分别记录。
接下来先让用户做短时真人试播，依据识别错误和停顿分段结果再决定升级 ASR。
之前的导演边界与跨话题记忆问题继续保留，按用户要求优先放到真实语音场景中复现。
