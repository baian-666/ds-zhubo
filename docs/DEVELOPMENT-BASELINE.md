# 本机直播助播：需求与开发路线

更新：2026-10-11。性质：需求对齐与后续实施基线。代码现状见 STATUS.md，本文的目标架构不代表已完成。
本文件取代 PROJECT.md、HANDOFF.md 中旧的云端优先开发顺序。最新用户偏好：没有现成语音服务账号，按省事优先选择。

## 用户需求基线

| 需求 | 交付边界 |
| --- | --- |
| 本机直播助播 | Windows 本地运行；真人主播主导，小鲸鱼自然参与、接梗、选择性回弹幕 |
| 低延迟与主动性 | 明确交棒快速响应；模糊机会由同一模型判断并拟稿；可等待、短文字/表情回应、接话或停止 |
| 同一个角色 | 小鲸鱼人格沿用已导入的 qq-bridge 直播改编版；导演和助播在聊天中共用角色，用公开简短理由解释行动 |
| 人工/自动对照 | 共用 DeepSeek、人格、语音服务、音色和上下文规则；只切换谁决定何时开口 |
| 形象与表演 | 使用已收到的 DS鲸鱼娘运行包；先验收基础形象、数个显著表情和口型，再扩动作；80 个 GIF 是另一类聊天素材 |
| 易用控制台 | 右侧集中真实麦克风、模拟主播与模拟弹幕；中间聊天气泡、字幕与决策时间线；日常保留开始/停止、打断和模式切换，调试折叠 |
| 网页与桌面 | 按最新请求先完成 Electron 本机试播，复用共享模块；网页保留同一控制台与备用舞台入口，两个舞台中只有一个拥有收音/发声权 |
| 真实语音优先验收 | 用真人停顿、附和、接管和打断检验导演；影响链路正确性的故障先修，语义调参结合人声证据再做 |
| 凭据与已有修改 | 密钥只在本机忽略 .env，不输出、不提交；不覆盖旧修改、原角色压缩包或授权说明 |
| 后续直播平台 | B站/视频号是最终目标，本阶段模拟弹幕，先完成本机音视频闭环与 OBS 录制试验 |

非当前交付：游戏操作、云端部署、完整多平台管理、模型训练、声线克隆、长期记忆系统、通用 MCP 工具平台。
视觉和 GIF 回复保留为后续需求，不能拖慢第一版语音试播。

## 重新核对的结论

保留 AIRI 固定提交 34576c19f618a04e616657089f0688a8637873f2 和现有 Node/pnpm 工具链，不为接入本轮功能升级整套上游。

源码已核实：
- hearing.ts 和 voice-input-session.ts 提供音频输入、VAD、识别和消费者回调。
- speech-runtime.ts、services/speech/pipeline-runtime.ts 和 pipelines-audio 提供文本输入、分段、合成与播放队列。
- scenes/Stage.vue 有音频播放、Live2D 口型和取消入口。
- vision 的 inference/store 与桌面截图 composable 已有实现。
- shared stage-ui 可供网页和 Electron 复用。

复用仍有实际连接工作：
- 识别结果不能同时触发 AIRI 默认聊天和 cohost 两次回复。
- speech intent 可接外部文字，但 Stage 的双向 WebSocket 语音服务走聊天生命周期的另一条路径，不能假定任意服务只调用 openIntent 就能工作。
- 部分 TTS 路径在返回音频后检查取消，不能据此声称云端在途合成请求已经中止。先保证本机立即停播、迟到音频丢弃，再按供应商验证请求取消。
- 当前 cohost 自动回复依赖浏览器轮询消费候选。后台/刷新可能漏接，语音主线需移到服务端统一消费，界面负责显示和控制。
- AIRI 中已有供应商配置不等于凭据符合本项目约束。云端密钥放本机服务，前端只配置受限本机入口。

## 目标分工

~~~mermaid
flowchart LR
  MIC[主播麦克风] --> AIRIIN[AIRI 采集与识别]
  AIRIIN --> COHOST[cohost 现场与导演]
  DM[模拟弹幕] --> COHOST
  COHOST --> DS[DeepSeek：判断 / 回复]
  DS --> COHOST
  COHOST --> OUT[AIRI 分句发声与角色表演]
  OUT -->|播放完成 / 打断| COHOST
  COHOST --> UI[聊天与决策时间线]
~~~

AIRI 负责设备、供应商适配、角色、播放与口型。cohost 是唯一直播决策与回复执行入口，保留现有自主参与、规则边界、短期现场与历史、队列与冷却。
用现有 integrations/airi 补小范围适配，可重放保存。跨窗口用 AIRI 现有 Eventa，服务边界按现有本机 HTTP/SSE 扩展。
使用有界事件、话轮号、片段号和执行回执，避免重复生成、重复播出和旧回答复活。不建立另一套完整聊天引擎。

## 首轮语音选型：省配置与开发成本

按用户“没有账号，省事优先”的选择，首轮采用一个硅基流动账号：
- ASR 候选：FunAudioLLM/SenseVoiceSmall。
- TTS 候选：FunAudioLLM/CosyVoice2-0.5B，先用内置中文音色，听过样本后确定。
- DeepSeek 对话仍使用现有服务与模型，不迁移已有配置。
- AIRI 复用兼容语音入口；cohost 本机代理仅转发所选识别/合成端点，固定供应商目标，不做任意 URL 转发平台。
- 尚无该账号/凭据，未进行实际调用；注册、当前模型可用性与付费开通以用户账户为准，不声称已测价格或最低费用。

官方资料：
- https://docs.siliconflow.cn/docs/api/audio-transcriptions-post
- https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech

取舍必须明确：以上 ASR 文档是上传音频文件后返回文字。首轮由 AIRI VAD 切短句后提交，不能称为实时流式识别。TTS 使用 AIRI 文本分句后分别合成，不能称为已接双向流式语音。
这条路线用于最少接入工作取得真人基线；若识别/端点等待导致延迟不合格，应先换流式 ASR，再做平台和装饰功能。
备选已有实现是 AIRI Aliyun NLS 流式识别；其 access key/app key 和流式代理配置更复杂，只有首轮实测需要时启用。
不同时接多套服务，不先部署本地大语音模型。先验收 20 段中文样本与实际首声延迟，再固定供应商。密钥仍只在 .env。

## 分步交付和停止扩展的条件

1. **角色与最小可见表演。** 从内层模型包建立忽略目录中的适配副本，保留原资源。加载鲸鱼娘，验证高兴/生气/疑惑/脸红等代表性动作及恢复；支持哪些写清楚，回执不代替画面验收。
2. **语音服务小样本。** 注册一次语音服务、密钥写本机 .env。先验证 20 段中文和短句合成，不启动完整对话。关键错字、切句和耗时不合格时只调整供应商/采集方式，避免带着错误输入调导演。
3. **唯一的真实语音闭环。** AIRI 识别→cohost 决策→回复流→AIRI 分句发声/口型；把自动执行移出网页轮询。按钮打断、旧音频丢弃、语音所有权与已播片段记忆必须通过。可先按已完成音频片段保守确认历史，不猜测逐字进度。
4. **真人对照与针对性修复。** 人工/自动各用同一套配置。明确交棒、长讲述中停顿、短附和、长句叫停、密集弹幕、后台与刷新、跨话题回顾；再做 10 分钟自由试聊。分别记录识别、决策、生成、首声和真正停止时刻。
5. **后续演出与直播。** 再扩更多动作、GIF、视觉和 OBS/真实弹幕。只有前一步达标后才进入下一层产品扩展。

试播目标沿用初始交接，均为待测目标：
- 10 次明确交棒至少 8 次顺利回应，不重复发言。
- 10 分钟明显错误抢话不超过 1 次；普通“嗯、对”不取消正在说的话。
- 明确交棒结束到首声争取 P50 ≤1.5 秒、P95 ≤3 秒；分段 ASR 不达标先换流式，不能改名为低延迟通过。
- 按钮触发到本机停止播放争取 ≤300 ms，且旧话轮永不复播。口头叫停另测从声音开始到停播的总时延，不与按钮混算。
- 不循环识别自己的回放；角色嘴随实际播放动，停止后归位。
- 一次自主决定包含拟稿，明确交棒走快速路径；不额外串行调用“导演模型→回复模型→表演模型”。

## 后续开发约束

新增组件前先列现有实现入口和缺口。首先验证端到端可用，再扩大服务、动作和界面选项。
生成首字、合成结束、播放开始和真人体验分别记录，模拟设备、合成音频、人声验收分别报告。
只运行本次改动相关和仓库强制检查；不反复读取全部历史，不展开无关修复。
检查现有修改再落盘，角色资源和音频样本留在忽略目录。凭据不写浏览器配置、不出现在日志。
不以测试数量表示自然互动完成，不以“可复用”表示已经桥接完成。
