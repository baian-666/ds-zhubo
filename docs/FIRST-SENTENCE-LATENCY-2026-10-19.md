# 首句等待优化与真实音频复测

2026-10-19。承接[上一轮4.16秒](TURN-LATENCY-2026-10-19.md)，本轮实现首句交付、文字/PCM准备复用及连接保护，后端已更新生效。最终版同一故事两遍为3.21、2.62秒，长附和不停、接管750ms停声、普通长讲话660ms停声；仍未稳定达到约2秒，也未完成人类自然度验收。以下保留全部候选，包括失败。

## 实现

- 普通闲聊首项可用简短的 `answer` 记录，表示固定的 `reply_host`；保留发言意图、完整短分句和理由。等待、停止、主持控制、反馈学习和其他动作仍使用原完整决定格式。首项校验后才能发声，后文仍是同一次模型流，不增加首句前的规划调用。
- 本地识别段结束后的准备与正式判断可以重叠。正式判断仍按原时间启动；仅与最终转写一致、仍有效的准备回答可胜出，准备中的wait不增加等待。赢家接管流与PCM，败者取消；同一时刻都完成也只能保留一个，避免遗留模型流。
- 只为前端不会再次拆分的首条文字预合成：不超过24个源字符、无内部硬分句符或换行。该PCM以相同文字精确领取一次，可以边合成边播放；新讲话、转写修改、候选失效时丢弃。其他首句按原路径合成，不把整段准备误当首句重复发送。
- 把准备提示移到长提示词后部，避免在共同前缀前插入内容。记录模型首token、首条记录、输入token/缓存命中；缓存原已自动启用，本次没有“新开缓存”。
- 真实试验发现后台空任务预热会借走最后一条可用连接。现仅在至少两条空闲连接时借用一条，始终给正式回答留一条；否则后台自行建连接。两条前台合成并发上限不变。
- 增加首句PCM来源和ASR最后确认句的计时。准备PCM可能早于HTTP领取请求，汇总不再把后句PCM误当首句。
- 未修改前端话轮保护、本地650ms结束阈值、640ms未知暂停/1800ms未知取消；未更换模型、音色或启用Qwen语气指令。讲话过程中旧的完整回答准备实验仍默认关闭。

## ASR收尾结论

[Fun-ASR官方参数文档](https://help.aliyun.com/en/model-studio/fun-asr-client-events)允许200–6000ms分句静音阈值，但降低参数不等于模型最后一个词会更早返回。650ms样本中最后的“资”在音频结束约1.17秒后才到；最后确认句与task-finished基本同时到达，因此简单绕过task-finished没有可观收益。400ms试验也未显示收益，未发布这个调整。
