# qq-bridge 的自主参与机制与直播导演借鉴

审阅日期：2026-10-10。源码固定到 Derpyu520/qq-bridge 的 9df6a7e7fc5abcb36793337f778483bd442a3d2d。
本次仅阅读公开源码；未安装依赖、未运行 QQ/DSH、未验证作者视频的实际效果。参考副本位于忽略的 data/references/qq-bridge。

## 结论

DSH 是 DeepSeek Harness。值得借鉴的是 reserved2（二代仿真）的事件与工具循环：消息持续入库，运行时唤醒模型并提供现场快照，模型通过工具自行选择查看、发言、等待、设置下次唤醒和记录待续念头。普通模型文本不自动发送。MCP 是动作接口；“融入思维链”在这个仓库里可见的实现是角色协议、工具调用和外部调度，不是修改模型底层推理算法。

主程序 bridge.js 当前 11036 行，QQ 接入、控制台、鉴权、审计及各代兼容也包含在内；理解自主参与不需要通读所有代码。

## 已核对的关键源码

链接均固定到审阅提交，后续主分支变化不会改变此记录。

- [二代角色协议](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/dsh/agent-presets/qq-chat-v2/agent.cordis.yml)：普通文本不自动外发；工具负责看、等、发、已读与唤醒；提示选择性参与与主动接话。协议和具体群友人设需要区别对待，不能直接复制全部行为偏好到知识分享助播。
- [工具定义](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/mcp-snowluma-safe.js#L427)：未读、最近消息、已读、唤醒配置、发送及等待。qq_send_message 会调用桥接发送 API，并把成功或错误反馈给模型。
- [现场缓存](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L9081)：接入消息先放入 recentMessages 和 unread，并分配本地 seq，不以是否回复为入库条件。
- [唤醒判定](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L9314)：仍有规则，包含 @、名字、关键词、指定成员、提问与概率。规则提供思考机会，不直接生成固定回复。
- [现场快照与已读水位](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L9353)：追踪实际展示给模型的消息，限制确认范围，避免模型思考期间新来的消息被一起清掉。快照直接随唤醒提供，可省一次取消息工具往返；快照有字数/条数上限，partial 表示需要继续获取，不是无限上下文。
- [主动机会定时器](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L9766)：结合空闲、概率、最近发言及未过期 pendingThoughts 等安排主动检查。不是模型在没有请求时持续思考。
- [真实等待执行](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L5724)：根据用途等待新消息或补足最后来信后的静默；新消息重新计算静默。合批、读取、推理已经经过的时间计入，不重复等待整段。
- [发送时再次检查](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L7447)：排队后临发送再次检查状态/权限，收集失败信息。可借鉴为直播的“开口前检查主播状态与话轮版本”。
- [普通文本不自动发送](https://github.com/Derpyu520/qq-bridge/blob/9df6a7e7fc5abcb36793337f778483bd442a3d2d/src/bridge.js#L10653)：reserved2 明确走内部日志分支，而非 QQ 发送。

## 对 ds-zhubo 的映射（建议，尚未实现）

1. 持续现场：把主播最终文本、弹幕及已实际交付的助播内容维护为有界现场输入；解决“年糕”未传给模型的问题。
2. 同角色动作：同一助播选择等待、申请接话、接梗、挑选弹幕、撤回计划；导演气泡呈现简短决策说明，助播气泡呈现公开发言。
3. 事件驱动：新最终文本、主播停顿、重要弹幕、到期检查触发判断；允许选择安静，避免按每条弹幕逐一调用模型。
4. 思考期间的新消息：带现场序号与话轮版本；执行前重检，新情况可取消过时计划。
5. 执行反馈：分清请求发言、生成完成和实际播放；工具成功不自动等于已经播完。
6. 未说出的念头：候选有有效期，话题变化后丢弃，适时短补充，不无限追问。

## 不能原样套用的群聊节奏

config.example.json 中：唤醒合批 8000 ms，收到新消息后的静默下限 10000 ms，睡前观察 300000 ms，主动检查间隔 30–90 分钟。它们是群聊默认配置，不是实测端到端耗时，也不能简单相加：代码会把已过去的时间计入静默。

这些尺度不适合直播秒级接话。明确交棒保留直接流式回复；主动参与判断需要并行、合并事件、限制在途请求、过期丢弃。MCP/工具参数完整性可能影响首字，须实测，不保证无额外延迟。

## 开发取舍

先在现有 DeepSeek API 与话轮调度上实现有界现场和少量结构化动作，保持人工/自动同模型同人设。工具接口可再封装为 MCP。QQ 网关、群管理、DSH 会话鉴权和黑话研究不是当前里程碑的必要依赖。若后续复制源代码，应保留项目 MIT 许可要求的版权与许可声明；本轮只形成分析，没有移植其代码。
