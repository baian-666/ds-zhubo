# 自主参与：角色、节奏与运行边界

2026-10-18。小鲸鱼使用同一个参与模型决定带话题、陪聊或倾听。默认持续主持，程序管理播放、静默唤醒和人工控制，不替她编节目脚本。

## 持续主持更新（2026-10-18）

- 可以对她说“你先播着，我去忙点别的”“你继续主持”。同次导演调用返回 hostingControl=start，当前主播最终话语通过校验后开启或恢复。观众、旧记录、临时识别、引用、假设及否定不能开启。
- 开始互动或主动开启收音后，若未安排后续观察，连续安静30秒会再判断。默认不因12轮、12次判断或10分钟无人输入结束。仅打开软件、明确暂停/关闭、静音和断线不会自行恢复。
- 模型正常选择的1～10秒续讲、15～120秒观众等待仍保留，均从完整播放后计时。模型选择0/缺失计划时，持续模式使用30秒静默观察；不保证第30秒就出声，也不强迫每次观察都发言。
- 缺失closing、判断/播放失败不复播旧内容：30、60、120秒后按新现场重试，连续第4次失败暂停。密钥错误直接暂停。停播/静音/断线/换角色会撤销重试。
- 明确“关闭自主模式、保持安静等我叫你”可返回 hostingControl=pause。用户正常插话撤销原定观察，讲话期间不唤醒；没有最终识别的声音结束后仍可重新静默计时。
- 主持按钮允许同一人工控制期间的后台状态更新，不再因正常播放或新输入导致revision冲突。跨越后续暂停/停止的旧请求仍被拒绝。
- 细节、失败样本与验收边界见[持续主持修复](HOSTING-CONTINUITY-2026-10-18.md)。下方2026-10-17证据保留为历史，有限模式仍可在隔离测试中使用。

## 怎么用

1. 正常开始文字聊天或收音即可。也可以在「直播节奏」点「让她自行安排」。方向可以留空。
2. 她自己决定主题和参与方式，不必手动切换主持/助播。人类输入和弹幕都能改变下一次判断。
3. 「暂时留白」下会区分两种情况：只等新输入，或已安排稍后再观察一次。继续同一话题时也会短暂停顿，导演理由会说明为什么继续或让话。
4. 「暂停自行安排」和明确叫停取消安排。恢复需要点击继续或主播明确说“你继续主持”。观众不能解除人工暂停。
5. 「仅回应输入」关闭自主唤醒。正常输入回复仍保留。重启不恢复定时计划，打开窗口本身不触发发言。

## 收尾交棒更新（2026-10-17）

自主流式回复以台词后的closing为准，开头节奏仅为草案。继续展开1～10秒；交给观众0或15～120秒；听搭档0。持续模式下0会进入30秒静默观察，缺失确认使用有上限的延迟重试，不沿用开头草案。加入主持指导/正反例及真实交棒后的等待时钟；不增加模型调用、不挡首句。原机制与370项历史证据见[导演交棒](DIRECTOR-HANDOFF.md)。

## 模型决定什么

- 同一次流式调用选择 action、台词、语气、表情和参与安排。没有在回答前新增一个规划模型。
- `hostingIntent`：`lead` 组织内容，`support` 陪聊，`listen` 倾听。它是可变化的行为意图，不改变角色人格。
- `hostingTopic` 是可选的自主主题，不要求每轮另开游戏或反复讲规则。
- `hostingPace`：`continue` 表示还要展开同一话题，已交付回复后可选1～10秒；`yield` 表示留给别人，已交付回复后可选5～120秒。普通助播和边听短反应的长度规则不变。
- `revisitAfterSeconds`：0只等新输入；正值安排一次观察。缺失/非法值不授权唤醒。wait/react 只允许 yield 的15～120秒或0，不能借 continue 快速空转。旧的无pace计划按yield兼容。
- 自行安排的流式台词不再限制一两句，可以同一次调用讲完整观点、例子和小结；仍受800字/10条流式记录上限约束。首句继续先输出，后文接现有语音管线，不增加首声前规划调用。
- 间隔是播完后的观察等待，不是下一轮首声保证：之后仍有模型、合成和传输耗时。同一段内优先一次说完整，不拆成一句一次唤醒。
- 到时间只是再次判断。模型仍可等待、换题、接弹幕或选择不再唤醒。运行时不再固定“三轮没人回就停止”。
- 讲话后的安排在整轮音频实际播完后计时，且期间没有更新输入才生效。wait/react 的安排在决定被接受时生效。
- 新输入使旧意图失效。新讲话开始会撤销未触发的定时观察。晚到的旧模型结果不能覆盖新现场。
- 现场信息包括最近记录、已交付历史、候选弹幕、播放/人类讲话状态、当前参与角色、无反馈时长和剩余预算。不会每轮塞入整个历史库。

## 程序保留什么

- 单话轮播放、人工停止/静音、舞台所有权、取消与迟到结果丢弃。模型不能自行授予权限或解除暂停。
- 默认持续模式无总轮数/时长上限。有限模式保留12次判断、12条话轮、10分钟上限，供隔离回归使用。
- 新现场输入重置无输入判断预算；已经完成的段落只在新输入后重新观察。定时器不能自行重置预算。
- 判断或播放失败、断线、切角色会暂停或撤销安排。资源限制不是模型必须用完的任务。
- 纯后台弹幕仍有250ms汇集和最短3秒判断间隔。新消息加入下一批，不逐条额外调用模型。
- 原助播主动补充的15秒冷却不阻止自行安排中的正常接话。边听边理解的短插话保护保持原实现。

## 弹幕选择

- 自行安排期间，带题和陪聊都不要求点名、提问或点选，不设20秒全局/60秒同观众回复冷却。模型可挑选、略过或继续原话题。
- 弹幕保留90秒，队列最多128条，每观众最多3条待选。同人同文10秒内不重复入队，平台稳定消息ID继续去重。
- 按观众交错排序后最多16条进入模型。人工点选提高同层优先级，不绕过播放保护。
- 正在说话时先排队。已选中的主回复从队列取走。顺带回应其他候选不等于逐条完成，仍可能重复点评，需要评估自然度。
- 退出自行安排后恢复原助播限制。后端向界面提供实际等待原因。长播放后的候选执行也使用90秒有效期，不再错误地按20秒拒绝。
