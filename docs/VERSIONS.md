## 统一存档入口

双击根目录 `保存项目版本.cmd`，或使用项目固定 Node 执行：

```powershell
.\data\toolchains\node-v26.7.0-win-x64\node.exe scripts/version-checkpoint.mjs create before-my-change
.\data\toolchains\node-v26.7.0-win-x64\node.exe scripts/version-checkpoint.mjs list
.\data\toolchains\node-v26.7.0-win-x64\node.exe scripts/version-checkpoint.mjs verify <存档编号>
```

每个新编号都记录时间和标签，内容在 `data/version-archives/checkpoints/<编号>/`：

- `source/`：当前源码、文档、测试、集成补丁、依赖锁和启动脚本，包含未提交及未忽略的新文件；另记已删除路径和 Git 基点。
- `session.sqlite`：SQLite 在线备份，包含 WAL 中已提交的数据，附完整性检查。不会直接复制正在写入的数据库文件。
- `dependencies/`：AIRI 的 package/workspace/lock 文件；完整桌面文件另存 `data/version-archives/desktop/<构建号>/files/`，多个存档复用同一份。
- `manifest.json`、`manifest.sha256`：源码/数据库/桌面全文件校验、所选当前/上一版桌面、开始/结束时间和恢复边界。

源码、桌面选择或依赖在抓取期间变化会拒绝生成完成态存档，等待编辑结束后重试。
不完整目录以 `.pending` 结尾，不列为可用版本；既有存档不会被覆盖。
密钥文件排除，源码/桌面若含已知环境密钥则拒绝存档；数据库属于本机私有数据，整个存档目录禁止直接推到公开仓库。
这里的哈希用于发现缺失或改动，不提供外部签名。

## 每次改版的保存规则

1. 行为修改/更新前保存 `before-主题`，保证有可比较的起点。
2. 完成检查、部署后保存 `verified-主题`；在对应专题记录编号、启用内容、测试范围和失败项。未部署或未试听必须注明。
3. STATUS 只保留当前有效结论和专题链接；不重复粘贴每轮日志。
4. 清理普通构建前核对存档引用，保留存档中的桌面完整文件；不把“只有数据库备份”标成完整可回退版。

这是开发流程要求和手动入口，目前没有把自动存档接入每次编辑或所有部署脚本。
Git 提交/标签仍适合管理源码里程碑；本次保留现有工作区和提交历史，未把其他进行中的修改擅自归为已发布版本。

## 恢复步骤与尚未覆盖的部分

先选择存档并运行 `verify`。在新目录展开 `source/`，按保存的 AIRI 提交、补丁和锁文件准备依赖，再对该版本运行检查。
不要将整棵旧源码直接覆盖当前工作区，以免留下不属于旧版的新文件或丢失近期修改。
桌面存档需放回对应 AIRI 构建目录，并满足依赖锁检查；单独复制桌面目录到另一台机器不能保证运行。

生产切换前先另存当前状态并停止会写库的后端，然后使用相匹配的数据库副本；保留切换后新产生的数据。
数据库结构目前为 SQL v3，场次检查点为 format 2；存档清单自身为 format 1，三者不同。
只切换桌面的既有入口仍是 `./scripts/local.ps1 rollback:desktop`，它不会同步回退后端或聊天库。
完整恢复需要按 [场次记忆](SESSION-MEMORY.md) 和 [配置仓库](RUNTIME-SETTINGS.md) 核对迁移兼容性。本次只做存档校验和隔离恢复读取，没有切换生产服务。

以下仍是独立恢复材料：`.env` 密钥、`data/desktop-profile` 中的导入模型/外观、本机安装的工具链及依赖、
`D:/ds-zhubo-models` 外置语音模型、试听录音和实验日志。不能把此存档称为整机备份或可分发安装包。
完整存档与项目同在 D 盘。GitHub 已保存源码，但数据库、模型等私有材料仍需另一个磁盘或私有远端副本。
