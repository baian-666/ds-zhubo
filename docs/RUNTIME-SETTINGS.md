# 普通配置与角色仓库

## 当前实现（2026-10-15 收尾）

普通配置现在包括 TTS、DeepSeek 回复模型、SenseVoice 识别配置及完整角色目录。它们保存在同一个 SQLite 中，但每个模块有独立修订号；清空本场不清配置或角色。

| 日常入口 | 实际用途 |
| --- | --- |
| AIRI 设置 → 意识／回复模型 | 修改当前 DeepSeek 模型，验证访问权后保存，导演和回复共用 |
| AIRI 设置 → 听觉／语音识别 | 查看实际 SenseVoice/SiliconFlow 配置，选择原生麦克风，默认跟随系统；下次开始收音生效 |
| AIRI 设置 → 发声／语音合成 | 保存服务/音色并用直播同一链路试听 |
| AIRI 角色卡、行为／性格 | 编辑当前人设；直播助播页显示当前绑定及仓库错误，提供显式重新读取 |
| AIRI 角色模型 | 本机模型、缩放、表情和授权；不复制另一端的模型文件 |

`runtime_settings` 继续存声音；新增 `module_settings` 的 `inference`、`recognition`、`characters` 三条记录。SQL `user_version:3`，聊天检查点仍为 `format:2`。服务注册表是 `packages/cohost-contracts/services.ts` 与 `speech.ts`，当前没有额外 LLM/ASR 供应商适配器。

模型更改先访问服务端模型目录验证权限，不调用生成；再检查请求是否取消、现场是否空闲、修订是否过期，事务提交后发布。识别设置不启动第二个录音器；采集中不允许切换识别服务。配置失败保留旧值，损坏记录拒绝启动，不静默以环境默认值重建。

角色目录首次导入已有原生卡，保留未知扩展字段，拒绝凭据字段。桌面主窗口通过原生 Pinia leader 动作处理设置窗口编辑，独立网页通过后端修订同步。旧草稿冲突不会覆盖新版本；选择“重新读取”前保存本机草稿。首次同步备份位于浏览器 `cohost/cards-before-repository`，冲突重载备份在 `cohost/cards-unsaved-draft`。

同一卡修改人设从后续回答生效，取消旧的候选判断但不截断正在播放的回答；切换角色身份取消旧角色输出。后端保留已选人设，舞台退出只释放其过期表演能力。话轮记录有效人设/推理/声音版本。

角色模型 ID 属于本地资源目录。自动导入形象不写回共享卡；另一端不存在的模型 ID 保留在卡元数据中，但不覆盖当前设备模型。直播模式隐藏无效的每卡供应商覆盖项，原始字段仍保留。

本次生产库副本迁移、两独立网页窗口互改、真实 Pinia leader/follower、重启、数据库故障、陈旧写入及原媒体回归均有验证。最终构建、数据库备份和实际 Electron 验收见 [STATUS](STATUS.md) 和 [架构验收](ARCHITECTURE-ACCEPTANCE.md)。密钥与 `.env` 保持原样；共享 Index 不属于本次重启范围。

回退 SQL v3 后端必须使用匹配的 v2 数据库备份和源码检查点 `data/architecture-configuration-verified-20261015/`。先停止后端并另存当前库及 WAL/SHM，再恢复备份；备份之后的新内容须另存。仅回退桌面不改变数据库，旧后端不能直接打开 v3。

## 历史：声音设置首批

更新：2026-10-15。沿架构路线收敛配置归属，复用现有本机 SQLite，不引入新服务。

## 日常使用

在 AIRI「设置 → 发声／语音合成」选择小鲸鱼的声音。直播助播设置中的「调整声音与试听」进入同一页。
桌面和网页共享实际使用的服务与音色；保存成功后，下一次发言及试听生效。发声时禁止切换，避免半句换声音。
页面显示持久保存或临时运行状态。普通启动使用持久保存，重启和清空本场均保留声音选择。

## 配置归属

| 内容 | 当前唯一来源 |
| --- | --- |
| TTS 服务、音色、修订号、更新时间 | `data/cohost-session.sqlite` 的独立 `runtime_settings` 表 |
| 可选服务、音色与已开放能力 | `packages/cohost-contracts/speech.ts` 共用注册表 |
| 模型服务密钥 | 本机忽略的 `.env`，不进入配置表或浏览器 |
| AIRI 角色卡、模型显示偏好、表情许可 | 保留当前 AIRI store 与根级同步，不在本批迁移 |
| LLM / ASR 选择、B站连接 | 保留现有入口；尚未统一到本仓库 |

首次启动没有保存配置时，导入 `COHOST_TTS_PROVIDER` / `COHOST_TTS_VOICE`，缺省值来自注册表。
后续以数据库为准，编辑旧环境变量不会覆盖已有选择；从 AIRI 设置页修改即可。
原 `.env` 字节保留，保存声音不再重写它。切换服务时使用新服务的默认音色，不继承旧环境变量的音色。
`--no-session-store` 或不传 `sessionPath` 的测试实例使用内存设置，界面明确提示重启不保留。

## 写入与失败语义

`RuntimeSettings` 负责严格字段校验和修订号，`SessionStore` 负责事务及进程租约。声音设置与聊天检查点使用独立修订号和生命周期。
只允许注册表内的服务/音色组合；未知字段、凭据字段和不支持的版本均拒绝。损坏记录不会被环境默认值静默覆盖。

保存顺序为：核对当前修订号 → 准备候选服务 → 检查请求取消及现场状态 → 原子保存 → 替换运行对象。
旧窗口、并发写入、验证失败、客户端取消或磁盘写入失败均保留原配置。普通配置不进入每轮模型提示，不增加模型调用或首声等待步骤。
话轮继续捕获有效声音修订号，试听和直播使用同一适配器。收音、表演、参与判断和后台任务的原有取消机制保留。
