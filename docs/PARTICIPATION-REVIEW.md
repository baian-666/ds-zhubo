# 自主参与审阅：可靠性与体验

日期：2026-10-10。审阅提交 108979b；业务代码未修改。独立模拟与浏览器探针不接真实模型、不修改用户当前场次。

## 已观察到的真实行为

- 跨话题回顾编造主播未讲过的细节：长对话第三段出现“猫转三圈”“面趁热拌”。server.mjs:113 在换题时清空 Scene，而 participation.mjs:27 的模型快照不带已交付 histories。快速回答带 history，参与拟稿不带，形成记忆差异。建议保留带话题边界的本场事实及来源，两条生成路径共用；缺失时说明没有记录。
- 第二段主播说“先别开药方，我还有后半段”后助播仍补吐槽。最后一句又构成完整笑点，属于需人评的边界案例，不能简单认定所有此类回复都错误；应加入持续持有话轮与明确交棒的成对评估。

## 尚需验证的风险与产品改进

- 公开回复目前依赖浏览器约 400 ms 轮询消费，准备结果只保留 1.5 秒；后台节流、断线、刷新时可能漏接。此次没有实测所有浏览器的后台节流。建议服务端负责执行与去重，网页只订阅。
- 简短精确叫停走规则；较长叫停句依赖说完后的模型判断。实际语音需独立测量“开始叫停→停止播放”，不能用判断耗时或模型自述代替。
- 导演气泡是模型的简短解释，不等同真实执行结果。应分别显示提出行动、实际执行/被取消/失效及原因，避免看到“准备接话”却没后文。
- 一键连续剧本、暂停/单步/重播和两模式对照能减少用户打字；真实与模拟结果应保持明确标识。
- 当前源码有后端密钥、回环绑定、跨站写入检查、文本 textContent 渲染和动作/候选验证。这次没有做完整安全审计，恶意弹幕的语义操纵还需专门评估，不能据此声称已经安全验收。

建议顺序：先解决遗漏话轮、弹幕取消风暴和多页面控制；再统一本场记忆与事实来源；然后做自由对话/压力对照并接最小语音。保留明确交棒的快速路径，避免在回复前增加串行模型判断。
