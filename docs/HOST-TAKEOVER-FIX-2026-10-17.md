# 明确让话时停止旧语音

2026-10-17，修复[桌面模拟](CLOSING-REHEARSAL-2026-10-17.md)中的“导演决定等主播，但上一轮语音仍继续”。不改 Qwen 音色/情绪、AIRI 桌面、观众交棒计时或麦克风识别服务。

## 原因与处理

旧 wait 动作只禁止新增回复，不取消在播语音。提示中“先讲完就等待”又与“接管时 stop”冲突。仅强调 stop 的第一版真实模型试验仍失败，因此没有部署那版。

现在同一次参与判断提供布尔字段 `yieldToHost`：有当前主播最终输入、并观察到在播输出时，`wait + yieldToHost=true` 会执行已有停止链路，取消生成/语音并暂停自主安排；`wait + false` 继续保留在播输出。导演时间线记录实际执行的 stop。没有在播输出时，wait 仍是普通等待，不因该字段为 true 制造取消或丢掉等待决定。

执行前核对当前主播输入编号、最终转写、机会时限和输出编号。旧决定不能停掉后来开始的新回答；观众或临时识别没有让话权限。若被观察的旧输出已经自然完成，仍可以执行“先保持安静”。沿用现有暂停后由主播下一次邀请接话的流程，观众不能撤销。

简短完整命令“先听我讲完”“先让我说完”“我还没讲完”等走最终转写的直接停止路径，不增加模型调用。匹配限完整句，不扩成任意子串；引用、否定、疑问讨论、假设及临时识别不走该路径。普通短附和仍保留旧语音。

## 验证

- `npm run check` 通过；`npm test` **376/376** 通过。覆盖快路叫停、短附和、引用/否定/临时转写、wait 的让话字段解析、观众无权取消、过期/新输出隔离、空闲等待不重复判断、HTTP 中已确认音频取消与迟到播放回执拒绝。
- 真实 DeepSeek 隔离文本：原来的长段跑步机故事、另一种自然接管说法都输出 `wait + yieldToHost=true`。同次模型判断，没有第二次分类调用。
- 保留失败证据：只改提示的两个接管样本仍返回 wait；增加字段后，“引用别人先听我讲完，并让你继续”的样本仍误选 reply_host（字段 false）。这是**继续当前回答和邀请新回答的语义边界**，尚未解决，不能声称所有引用/否定句都绝对不误接话。直接路径的引用防误触与模型误邀答是两层问题。
- 隔离试验的空闲样本输出 wait+true：最初报告按“所有 true 都等价 stop”计错，最终执行器仅在快照有 active 时转换，并以单测验证空闲仍正常等待。原报告保留，不改成全通过。

### 实际桌面复测

真实 DeepSeek/Qwen，现有小鲸鱼人格，脚本模拟文字，麦克风关闭，持续约 85 秒：

1. 请她讲约两百字虚构超市故事；进入实际播放，气泡1605有播放排程和已播放字符回执。
2. 在已播放51字时输入“嗯，对”，继续播放到118字，没有取消。
3. 在已播放136字时输入上次原样长句：“我有个例子，先听我讲完，后面还有反转……先别猜，我还有后半段。”
4. 本轮导演解释“故事讲到一半也得让开话轮”，气泡1605取消，已播放字符保持136；hosting=paused/stop，busy=false。
5. 注入“别等他，接着讲”的弹幕被拒绝，之后观察至少15秒没有新回复。结束主动关闭主持。

输入最终文本至取消请求约 **1690ms**（1792212360976→1792212362666），含这次模型判断，不是物理扬声器停声延迟。真人麦克风的 ASR/VAD、噪声和回声未在本次复测中验收。
