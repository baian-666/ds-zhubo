# 话轮导演第一版

更新：2026-10-09。已实现规则导演、异步语义接口和播放反馈协议。没有接入 ASR、VAD 引擎、TTS、AIRI 或真实播放器；模拟通过不代表真人互动通过。

## 延迟设计

- `Director.event()` 同步更新状态，不调用模型。明确点名交棒、精确停止指令走快速路径。
- 客户端消费候选决定后直接启动主 AI；服务端重新检查是否过期、已消费、主播是否继续讲话或静音。
- 可选 `classify(snapshot, { signal })` 是异步旁路接口，默认未配置。最多一个正在执行的判断和一个最新待判断快照。新文本覆盖待处理快照并取消旧请求；200 ms 后结果失效。
- 适配器必须遵守取消并最终结束。不遵守取消的调用仍占用唯一槽位，不会不断创建新请求，快速路径仍可使用。本地同步模型推理必须放在 worker，不能阻塞 HTTP 主线程。
- 第一版不做推测性主模型生成，不增加串行模型判断调用。候选默认 2 秒过期；主动补充默认冷却 15 秒，每个话段最多消费一次。明确交棒不受该冷却限制，参数均待真人试播调整。

## 规则与边界

- `speech-start` 只观察声音，保留当前回答，并作废未消费的旧决定。
- 最终识别文本和 `speech-end` 都到达后，像“助播，你怎么看？”的明确点名模板才产生交棒决定。不凭静音长度单独判定句子结束。
- 800 ms 内、12 字以内的“嗯”“对”“嗯，对”等最终短文本视为附和，保留回答。词表不是完整语义理解。
- 单独的“等一下”“先听我说”等精确指令取消话轮；引用这些词的句子不会仅因关键词命中就取消。
- 复杂接管、未点名交棒、笑点和主动补充依赖模拟 `intent` 或未来分类器；第一版尚未自动识别。低于 0.85 置信度默认等待。
- 显式话题切换清空候选弹幕，并取消正在回答的旧弹幕。保留已有去重、容量、过期及冷却，尚无弹幕语义排序。
- 原 `/api/host-speaking` 和网页“我正在讲话，助播先听”仍是人工明确让话命令。语音适配器必须用新 `speech-start/end` 事件。

## 事件与生成接口

所有 API 沿用访问令牌、输入大小和跨站限制。`POST /api/director/event` 本身不调用生成 API。依次发送：

```json
{"type":"mode","value":"auto"}
{"type":"speech-start","utterance":1}
{"type":"transcript","utterance":1,"text":"助播，你怎么看？","final":true}
{"type":"speech-end","utterance":1}
```

`utterance` 在单场服务内为递增正整数。中间结果用 `final:false`；一个话段只接受一个最终文本，后续修订须用新编号。旧话段和重复最终文本不会改变决定。适配器应按源顺序发送，重连不复用旧编号。当前按服务器接收时间计算时长；真实语音接入还需源音频时间戳与抖动处理。

返回 `director.candidate` 时向 `POST /api/reply` 发送以下形式，编号必须使用实际返回值：

```json
{"source":"director","decision":1,"delivery":"text"}
```

过期、重复或被新讲话作废的决定返回 409，不调用模型。人工模式仍使用 `source:host/viewer`。网页提供模拟事件及“按导演决定接话”按钮，目前由人触发发送，不是连续自动语音运行器。

语义适配器或人工模拟使用当前快照的 revision：

```json
{"type":"intent","revision":3,"intent":"takeover","confidence":0.95}
```

`intent` 可为 `hold/handover/backchannel/takeover/stop/opportunity`。接口仅面向受信任适配器和人工联调，不能让弹幕直接调用。异步结果版本不同或机会过期时丢弃。

## 播放反馈

`/api/reply` 设置 `delivery:audio` 只改变生命周期，不会产生音频。所有 NDJSON 事件携带 `turn/audioId`；一轮对应一个逻辑音频流。`done` 表示生成完毕，`awaitingPlayback:true` 表示尚待播完。

播放器向 `POST /api/playback` 发送：

```json
{"turn":1,"audioId":"1:0","event":"started"}
{"turn":1,"audioId":"1:0","event":"progress","playedChars":4}
{"turn":1,"audioId":"1:0","event":"ended","playedChars":8}
```

- 事件为 `started/progress/ended/stopped/error`。除 started 外必须携带单调递增、且不超过已生成长度的 UTF-16 文本前缀偏移 `playedChars`。
- 根据实际播放进度和 TTS 对齐数据上报。不能精确对齐时只确认完整播完的片段，不估算未听到的文本；分片不能拆开 Unicode 代理对。
- 客户端出声前本地检查最新话轮、静音及主播语音活动；started 被服务器拒绝时立即停止。服务器校验不能消除网络竞态，真实客户端必须实现本地门控。
- 主播讲话或静音时拒绝新播放；已播放中的短附和不禁止后续进度反馈。ended 仅在生成结束且完整文本已播出时接受。
- 打断使旧 turn/audioId 失效。客户端必须立即停声、清队列；TTS 适配器必须取消并丢弃迟到音频。本版本只实现协议和模拟验证，没有实际停声能力。
- 已播前缀在结束、停止、失败或取消时进入历史；未确认文本不写入历史。文字模式仍保存完整成功回复。
- 15 秒无反馈，在下一次状态、播放或接话操作时清理话轮。未来客户端必须定期上报，断连时本地停止。当前没有音频守护进程和播放控制推送通道。

## 验证与下一步

使用已保存 Node 26.7.0，运行 `npm run check`、`npm test`、`npm run replay:director`。回放读取 `tests/fixtures/director-replay.json`，覆盖交棒、句中停顿、附和、打断，重复 1000 轮共 15000 个事件，输出本机 p50/p95/p99，不调用 API。

这些耗时只测同步调度，不代表主 AI 首字或端到端出声延迟。下一阶段接入真实语音和语义分类器，以同模型、人设、声音对比人工/自动导演；记录交棒至请求、首字、TTS 首音频、实际出声时刻，以及错误抢话、遗漏机会和有效主动参与。
