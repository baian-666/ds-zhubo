# 小鲸鱼语音与 Live2D 演出路线

2026-10-14：开发顺序已由[长期架构与迁移路线](ARCHITECTURE-ROADMAP.md)替代。用户已放宽开发预算，优先长期效果与效率；SoulLink仍暂不接入，VRM不作前置验证。下文保留历史讨论及试验边界，不作为当前实施清单。

制定：2026-10-12。状态：开发计划，尚未实施或验收。依据本项目当前实现、AMADEUS-REVIEW.md 与 LIVE2D-SDK-REVIEW.md；本计划收敛此前各候选建议，后续按此顺序执行。

最新覆盖决定（2026-10-13）：用户仍想用 IndexTTS2，先了解本地与云端速度后再继续。保留 IndexTTS 为优先验证候选；当前隔离安装/实测版本为 IndexTTS-2.5，不自动降级。用户此前否定歌曲参考的克隆效果，此次选择引擎不等于重新认可该音色；不能继续对歌曲或裁剪参考调参来替代用户选择。先验证常驻服务、参考缓存、固定短台词的首个可听音频与打断，避免直接把整文件合成耗时当直播首声。已有克隆结果为历史试验，未获认可，未接入助播。下方早期路线保留为历史。

最新用户方向（2026-10-13）：优先调好语音，并要求音色克隆，选择先用完整参考做 IndexTTS 试听。下方演出优先及 Aqua 优先顺序被本项覆盖。已收到参考、安装隔离 IndexTTS-2.5 并实际生成两条完整 10 秒参考的讲话小样，详见 VOICE-REFERENCE.md；用户听感及实时延迟待验收，尚未接入正式助播。

已核对本机固定 AIRI 的 index-tts-vllm provider：当前配置/模型目录为 IndexTTS-1.5，设置页明确提示 IndexTTS2 尚未支持。不能将存在 Index-TTS 入口等同于原生支持 2/2.5 情绪克隆。当前直播通路又使用独立的固定云端 TTS，不会因为修改 AIRI provider 自动切换。建议 IndexTTS-2.5 本地服务先独立试听，采用情绪向量避免额外文字情绪模型，再经本项目语音适配接入 AIRI 播放与口型；实际运行、首声及原生配置互通需要后续验证。

用户随后授权由开发者决定实际顺序。最终安排：把下方第 0 步的必要计时与第 1 步合并为首个开发批次，以可切换的 Live2D 演出对照为可见交付；不要求先完成独立的大型基准平台。先用现有音频验证表演，随后试听语音候选，再统一接入。阶段编号表示验证依赖，实际可交错；发现主要瓶颈时调整实现顺序，保留验收边界。

## 2026-10-13 额度与延迟约束（优先于下方候选试验顺序）

用户提醒开发额度可能吃紧，且细节堆叠不能损害生动与及时互动。首批范围进一步收敛为在现有演出执行器上实现情绪保持/自然收尾、降低无意义重复、保护播放与打断的对照版，随改动补必要计时。SoulLink 先作设计参考；只有现有执行器出现明确难以补齐的缺口、SDK 最小接入收益可证明时再引入依赖。下方 SDK Profile/engine 对照是有条件的后续项，不是首批必须完成的任务。

- 优先级：有效接话和停止 > 语音清楚/语气合适 > 表情连贯 > 复杂动作。安静倾听也是有效表现；不把微动随机变化当成更懂语境。
- 每次参与不因演出新增远程模型调用。即使同一次调用，扩大参数说明和动作 JSON 仍增加输入/输出与完整结果等待；普通句使用简短意图，复杂关键帧只用于明确需要的动作。不能仅凭“没多调一次模型”宣称零延迟成本。
- 动作不成为播放前置条件。音频就绪时优先出声，尚未到的动作用中性/已有合法状态过渡；过期计划忽略。新增协议若仍被完整工具 JSON 卡住，应测量并单独处理，而不是宣称已经可独立开口。
- 单一参数写入者，离散图层与连续姿态分开；明确打断时立即停嘴与废弃旧动作。状态连续性不得变成下一轮迟迟不恢复。保留鲸鱼娘已验证的专属约束。
- 首批复用既有音频和六类固定回放，先本地验证，最后少量真实调用确认。固定回放检验执行，不替代真实模型/真人验收。候选只有初筛通过才扩大重复采样，不在每次微调重跑大规模付费比较。
- 语音一次只试一个候选：先核实现有接口情绪效果，再按需要试 Aqua，IndexTTS 留作有具体质量缺口时的对照。避免维护三套正式后端。更换语音前记录版本和配置并支持恢复。
- 开发过程复用已固定版本的研究结论，除非依赖/问题变更不重复搜索和整仓阅读；按小批交付保存进度与精确复现方法，功能验证完成后不无故重复。不能保证精确的账户额度节省比例，也不以省额度省略必要检查或把未验证效果说成完成。

首批验收：同样台词对照可见更自然；无新增网络等待、叠眼、口型争抢和旧动作复播；用配对计时观察是否变慢。若只有装饰收益却增加首声等待、明显帧卡顿或维护复杂度，则不纳入日常路径。先保证一种效果可靠，再决定是否值得加下一种。

## 目标与架构选择

下一里程碑是十分钟真实语音互动：小鲸鱼能及时接话，语气与脸部一致，表演连贯，打断后停声并自然恢复。桌面主用、网页备用，测试不要求 B 站开播。

- 主链：现有识别 → DeepSeek 导演与回复 → 语音合成 → AIRI 播放与 Live2D。继续使用同模型、同人设，已有一次调用完成决定/拟稿/动作的优点保留。
- 语音：现有硅基流动路径是基线；本地首选验证 GPT-SoVITS + Aqua 的适配版本，IndexTTS 是情绪效果的对照候选。最终供应商取决于中文试听、实际首声与设备共用下的稳定性，暂不定为已选中。
- 演出：优先验证 SoulLink 纯本地 engine 的连续情绪、微动与混合，利用现有鲸鱼娘组件定义接入 AIRI；参考 Amadeus 的按句播放和收尾。是否作为实际依赖要等隔离验证，不承诺直接替换当前执行器。
- DeepSeek 提供简短情绪/表演意图和可选动作序列；本地执行器负责帧间变化。不默认新增 Embedding 分类、独立动作模型或反思调用。参数计划迟到或失败不能阻止语音开口。

## 第 0 步：建立可比较的基线

首个开发批次先完成这一小步，并准备第 1 步的本地演出对照。

1. 补齐同一话轮的计时：主播结束标注/端点确认、识别完成、导演开始/决定可用、首段可合成文本、TTS 请求、首块音频、首个非静音播放、播放结束/取消。时钟以同进程差值为主，跨进程需关联并校准，不直接相减混用时间源。音频设备写入与真实扬声器出声分别标注，必要时用回环录音核对。
2. 固定六组材料：平静解释、被夸、被逗嘴硬转笑、安慰、长句、多句情绪转折。另测主播换气/附和/明确打断与弹幕同时到来。语音试听使用固定虚构台词，不发送用户历史。
3. 对照入口放在调试页面，日常侧栏继续简洁。先重用现有试听与场景脚本，不新建完整产品控制台。
4. 输出：可回放语音/表演样本、每阶段耗时、失败原因。显示首声中位数与较慢请求；统计样本不足时不称稳定 p95。区分冷启动与预热、TTS 单项与全链路。

通过条件：定位等待主要在 ASR、完整导演拟稿、TTS 还是播放；记录可复现，正式场次和设置可恢复。未达到之前不以更换供应商代替问题定位。

## 第 1 步：Live2D 小范围对照，无需新音色

- 从已测量的鲸鱼娘参数建立最小 Profile：眉眼、嘴角、头部、身体及视线。尾巴和道具先沿用现有受限组件，保留 44 个原生项目。
- 比较现有演出与 SoulLink 本地 engine；每次只启用一个参数执行器。统一安排口型、原生表情、明确动作、情绪底色和微动的控制权，不叠加两套眨眼/呼吸/口型。
- 初期用同一录制或合成音频、同一表演意图，避免两次 AI 不同回复干扰比较。若固定输入有效，再接已有 DeepSeek 的真实选择，不能把固定脚本效果当成 AI 自主验收。
- 必须保留：眼型/手势族互斥、离散开关完整切换、非零中立值、人工改动、打断和断联释放、旧话轮隔离。新增跨句情绪平缓变化与正常句尾收尾；明确打断时立即停嘴和停止旧动作。

通过条件：上述六类回放可见、自然度由用户比较；无两套眼睛、无持续摇晃、无口型争抢，恢复正确，演出不成为语音播放前置等待。若 SDK 适配成本明显超过收益，仅借鉴机制，继续改现有执行器。

## 第 2 步：选择语音后端

顺序：验证现有供应商情绪指令是否通过当前 API 实际生效 → GPT-SoVITS + Aqua → 若前者中文情绪/音色仍不理想，或需要确认质量差异，再试 IndexTTS。一次只加载一个候选，与 AIRI/识别共用电脑实测，避免多套 GPU 模型互相挤占造成无效比较。

- 未有角色参考录音时，用来源清楚的可用样本验证链路和情绪；不能据此宣布小鲸鱼目标音色已完成。最终音色需用户选定适当参考材料；不默认上传私人音频或训练。
- 固定文本、标点、音量与目标风格；支持克隆的候选尽量使用同一参考。与云端预置音色比较时明确音色不同，不能把音色偏好直接归因于引擎。情绪表达按各后端原生能力适配并记录。
- 测首个可听音频、句间空隙、读音、身份一致性、开心/吐槽/安慰区分、长句、显存以及打断。初筛每套相同台词；入围后再做不少于 30 次预热请求和单独冷启动记录。不得把作者硬件成绩当本机结果。
- 语音单项首声以预热后多数请求低于约 0.8 秒为争取目标，不是已实现指标或强行淘汰线。情绪与延迟取舍由同一中文样本的实际差异决定。

通过条件：用户能听出自然的情绪差异且喜欢音色；在本机 12GB 显存与 AIRI 共用时稳定；新增依赖的收益明确。若没有候选明显改善，保留现有供应商并继续改善播放链路，避免为安装而安装。

## 第 3 步：把声音与动作接成同一段演出

- 定义供应商无关的台词段、情绪强度、动作阶段和取消标识。单次 DeepSeek 输出可映射到 TTS 风格与 Live2D 意图；可选表演不合规时保留有效台词。
- 实现选定 TTS 的增量接收/播放、有限缓冲与取消。当前服务端与 AIRI 的完整 arrayBuffer 路径都要处理；仅把请求 stream 改 true 不构成流式播放。
- 以实际音频播放时钟触发每句表演和字幕。正常句尾适当停留后回倾听；动作计划迟到只接管尚未播放的部分或忽略，不从头重演、不延迟首声。
- 若第 0 步证实完整导演工具结果是主要瓶颈，另做有边界的协议改造：先确认参与决定，再发布可播放台词；保持一次模型调用与取消保护。未确认的临时文本不得提前播出，不用第二次回复调用造成新的串行等待。

通过条件：桌面和网页均通过，长句边合成边播放、清空队列有效，断线/打断/旧结果不会复播。原型变更运行 npm run check 与 npm test；AIRI 变更读其指导并完成对应类型、局部测试及实际渲染验证，补丁留在受跟踪 integrations，已有全仓阻断如实记录。

## 第 4 步：真实直播场景闭环

用户用耳机麦克风做十分钟对话，夹杂模拟弹幕即可，覆盖换气、附和、抢话、明确交棒、情绪转折和无须回答的时刻。技术回放可以由开发完成；自然度、音色偏好与真人接话体验需要用户短试听/实聊确认。

先沿用已有话轮验收目标：十次明确交棒至少八次顺利接话；每十分钟明显错误打断不超过一次；明确停止后尽快停声且旧回答不复播。全链路多数约 1–2 秒是争取方向，先测基线与较慢样本，不承诺所有请求一秒内。演出增加后应无可归因于动作规划的串行首声等待。

若主要问题仍在语音识别/结束判断，再推进本地 ASR 或提前识别；必须确认说完才提交，云端重复识别的成本也应记录。B站真实送达在方便开播后单独验证，不作为演出开发的前置条件。

## 暂缓事项

独立两阶段动作模型、任意全部原始参数开放、专门动作训练、音素级口型、复杂视觉、长期人格记忆及整套 Agent 框架迁移暂缓。它们可在上述试播明确出现需求后再评估。

完成当前规划不代表已经安装候选、接入情绪或实现流式播放。执行结果、用户偏好、未通过项目与最终后端选择继续写入 STATUS。
