# 同一气泡内语音长停顿修复

2026-10-17，用户反馈同一气泡的前后半句有时相隔很久。

## 原因与改动

- AIRI 原配置允许前两个片段在逗号等软标点处提前切开，每个片段都要重新启动一次云端合成。助播媒体桥现使用 `boost: 0, maximumWords: 24`：普通回复优先按句末切分，过长句子仍可在软标点处分段。已验证的导演分句仍可立即提交，不等待整条回答生成完。
- 后端原先将所有声音引擎的合成请求串行化，后一段必须等前一段生成完才能请求云端。Qwen 现允许最多两路在途请求，仍限制总待处理请求数为五；本地 Index/Aqua 仍独占模型。
- AIRI 原有音频顺序队列保持：后一句即使先生成好，也必须等前一句全部音频播完。话轮取消同时中止在途请求和排队请求，迟到音频不能复播。
- 这两处会放大云端延迟，但没有保存用户所述那次异常的逐段音频时间线，不能断言所有长停顿都只来自这两处。模型迟迟没有给出后文、云端抖动仍可能产生等待。

源码：[合成队列](../apps/cohost/speech-output.mjs)、[媒体桥](../integrations/airi/use-cohost-media-host.ts)。可重放 AIRI 覆盖文件保存在 integrations，未仅修改 vendor。

## 验证

- 先加入后端复现测试：第一段未结束时第二段必须开始。旧实现只启动第一段，测试失败；修复后通过。
- `npm run check`、358 项 Node 测试通过。新增云端两路并发上限、第二路释放后继续排队项、整轮取消后新回复可用的回归。
- AIRI 相关 15 项 Vitest、桌面 typecheck、两个改动文件定向 ESLint 通过；固定桌面构建成功。没有把这次检查描述为全仓 AIRI 重验。
- 一次当前克隆音色真实 Qwen 对照，固定两句话，无 ASR/LLM，无生产聊天写入：旧分句得到 3 个合成片段，新分句得到 2 个。按实际 PCM 到达与 AIRI 保留一帧的规则估算，二者的合成供给缺口均为 0ms，本次没有复现旧版偶发长停顿。新版第二句音频就绪约 3.21 秒，第一句估算结束约 6.54 秒。它们是单次到达/排程估算，不是物理扬声器测量，不代表提速统计或真人听感验收。
- 首次沙箱内云端连接失败，保留失败记录；允许网络连接后对照成功。Vitest 首次调用缺少工具链配置而退出，使用项目规定环境后通过，没有重装依赖。
