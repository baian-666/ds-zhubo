# 本机文字自主参与

更新：2026-10-10。当前已实现并真实调用 DeepSeek 验证；语音与 AIRI 口型尚未接入。

## 开发选择与实现

1. 现场上下文：保留最近 60 条、约 12000 字符的主播最终文本、弹幕和实际送达的助播文本。未被回复的主播发言也能被听见；模拟助播答案不进入真实模型现场。清空本场会清空上下文，切换话题清掉现场观察与旧弹幕。上下文只在本机进程内存中，重启不保留。
2. 同一角色选择行动：明确交棒沿用流式快速回复；其余机会让相同 DeepSeek 模型、相同基础人设一次调用 participate，返回 wait / reply_host / reply_viewer / stop、简短理由及拟稿。邀请接话与主动补充分别标记；只有主动补充受 15 秒冷却。没有新增 MCP 服务，也不依赖展示模型思维链。
3. 判断与拟稿一次完成：自主回复消费已准备的文字，不再串行调用另一轮生成。控制台把“判断与拟稿”和快速路径“生成首字”分开显示；前者不包含 250 ms 合批和浏览器最多约 400 ms 轮询等待，不是实际出声延迟。
4. 执行复查：单个异步判断、4.5 秒超时、主播机会 6 秒、候选决定有效 1.5 秒。新主播话、现场变动、静音、人工打断、模式改变、过期都会使相关旧结果失效；消费前再查是否安静、话轮是否空闲及弹幕冷却/过期。停止后不因旧弹幕立即重开口。
5. 已处理话轮记录：等待过的旧主播话不会在每条新弹幕到达时反复触发付费判断；现场无变化时不重复轮询模型。人工/自动切换和参与开关不会补答之前的旧话。
6. 网页操作：右侧新增“自主参与 · DeepSeek”，默认随本机密钥开启，但只有自动模式运行；切换模拟回复时关闭。导演解释与公开回答使用同一位“助播”气泡。新增“上下文铺垫 · 年糕 / 自然接梗 · 晾衣机 / 询问之前的猫名”场景。

## 最容易复现的测试

刷新 http://127.0.0.1:8787 ，选择自动导演、DeepSeek 真实 API，勾选自主参与。依次选择以下场景，每次点击“发送主播发言”，等中间气泡出现再发下一句：

- 上下文铺垫 · 年糕：包含“先听我把故事讲完”，应解释等待，不公开回答。
- 自然接梗 · 晾衣机：没有叫“助播”，应能接梗，并显示自主判断理由和拟稿耗时。
- 询问之前的猫名：明确交棒，直接流式回答，应知道叫“年糕”。

人工模式使用同一模型与现场上下文，但由“人工让助播接话”按钮决定时机。关掉自主参与可对照旧规则效果。

## 实际 13 步对话结果

同一 tests/fixtures/director-conversation.json，经真实 deepseek-flash 复跑：6 次参与判断 + 2 次快速生成，完成 7 条公开回复。规则基线此前为 3 条，并漏掉自然问句、总结邀请、猫名和相关弹幕。回复更多本身不等于更自然，下面保留具体行为供判断。

| 场景 | 实际行为 | 实际回复或依据 |
| --- | --- | --- |
| setup | 接话 | 那你这跑步机买值了，至少成了年糕的专属猫窝，这钱没白花。 |
| joke | 接话 | 算，而且你还少买了晾衣架，两千块摊下来比健身房年卡划算多了。 |
| implicit-question | 接话 | 别改名，跑步机这名字留着，还能骗自己说我是没时间跑，改了名连借口都没了。 |
| unsupported-handover | 接话 | 大家在笑的是这个落差：两千块的健身器材，最后年糕当观景台、你当晾衣架，一样都没浪费，就是没跑步。 |
| matched-handover | 接话 | 好笑，但笑完有点心酸，因为它好笑的地方太真实了，谁家还没件买了就吃灰的东西。 |
| ack | 等待 | short_acknowledgment |
| recall | 接话 | 叫年糕，就是那只把跑步机当观景台的猫。 |
| topic | 等待 | 主播明确说先把跑步机的事聊完、接下来自己要说怎么坚持运动，这是安排自己的发言，不是交棒给我，我先不插话，等他讲完运动那段再接。 |
| open-window | 回复相关弹幕 | 先接一句这位运动小白的：跑步机闲置，多半是目标定太狠，先从每天十分钟开始，跑完顺手把晾着的衣服收了，仪式感也有了。主播马上要说坚持运动，正好接着聊。 |

本轮参与判断含拟稿 1143–1303 ms，两个快速生成首字 493 / 634 ms；另一轮真实浏览器测试参与拟稿 1008 ms、快速生成首字 648 ms。都是小样本本机观察，不是性能承诺。

自动化校验：npm run check；npm test 63/63。原浏览器回归与新参与流程回归通过，覆盖气泡、同角色、完整现场记忆、一次拟稿不再调用生成、模拟开关、移动端宽度等。新浏览器真实测试 2 次判断 + 1 次快速生成，证实明确要求先讲完时等待、自然问句接话、快速回复能记住此前没回复的猫名。单元测试中延迟/过期/停止与新话轮竞争使用模拟模型或模拟在途话轮，未宣称是真实音频停播。

## 复跑入口

使用本机固定 Node（或满足 package.json 的 Node）运行：

~~~powershell
.\scripts\local.ps1 check
.\scripts\local.ps1 test
node --env-file-if-exists=.env scripts/director-conversation-trial.mjs --real --semantic
node --env-file-if-exists=.env scripts/browser-participation-smoke.mjs --real
~~~

浏览器脚本需要可用的 Playwright 模块，可通过 PLAYWRIGHT_MODULE 指向本机安装；默认不带 --real 时使用注入模拟模型。真实试验读取忽略的 .env，不记录密钥。详细公开对话写入忽略的 data/director-semantic-result.json；旧规则基线文件保留。--serve --real --semantic 会把独立结果保留在 8789，原基线 --serve 使用 8788。

## 限制及后续顺序

- 本阶段仍依赖文字提交和浏览器消费接话决定；浏览器关闭后不会完成公开发送。不是独立无人值守直播 Agent。
- 理由是模型给操作者的简短解释，不是内部思维链，也不是每次都可靠的事实。模型仍可能误判邀请、过早接梗或漏接；一次脚本不能替代自然闲聊。
- 弹幕仍必须被标为提问或人工点选，再经窗口、过期和冷却检查；模型在合格候选里按话题选择。普通笑声弹幕可作为现场背景，不自动获得发言资格。
- 下一阶段先做十分钟文字自由对话，记录抢话、遗漏、重复和首字/拟稿耗时；补真实打断与持续弹幕压力下的评估，再接主播 ASR/VAD、短句 TTS、实际播放回执与 AIRI 口型。网页版优先，Electron 后置。
