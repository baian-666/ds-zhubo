# B 站真实弹幕接入

当前支持 **blivechat 本机转发（用户已选）** 和自建 B 站官方开放接口两条路径。两者使用同一个弹幕队列、导演和语音/表演流程，不发送平台弹幕，不启动推流。桌面为主，网页版使用同一连接。现有官方适配保留，来源一次只选一种。

## 推荐：blivechat 本机转发

1. 双击根目录“配置B站弹幕.cmd”。它准备作者发布的 Windows 本地版 v1.10.4 并启动本机后台；本项目使用 **12451** 端口，避免本机另一个程序占用默认 12450。配置页在 http://127.0.0.1:8791/ ，本机工具在 http://127.0.0.1:12451/ 。
2. 在配置页选择“主播身份码”，打开 [B站互动玩法首页](https://play-live.bilibili.com/)，点击右上角“身份码”，按提示登录主播账号并取得自己的身份码，再回到本机密码输入框填写。若内置浏览器无法打开，在日常 Edge/Chrome 打开同一首页。blivechat 商店详情页是下载入口，不能当作取得身份码的直接入口。无需自建开发者应用，也无需给本项目 Cookie。身份码只保存忽略的 .env，不返回浏览器、不提交；DeepSeek 和语音密钥保持。房间号模式供兼容试验，可能打码、受限制或失效，推荐身份码。
3. 保存会通过已有本机控制权限只刷新弹幕来源，停止旧来源并保留聊天和收音，不重启助播；**不会自动连接**。回到 AIRI 设置 →“直播助播”中的“B站弹幕”，点“连接 B站弹幕”，请另一个观众发送一句普通弹幕。
4. “已连接”只说明本机转发通道建立。必须看到“B站观众”的消息和接收数增加才确认真实直播间送达。没有用户身份码/房间或真实消息前，不声称 B站已接通。

保存字段为 BILIBILI_SOURCE=blivechat、BILIBILI_RELAY_URL=ws://127.0.0.1:12451/api/chat、BILIBILI_ANCHOR_CODE 或 BILIBILI_RELAY_ROOM_ID。正常启动小鲸鱼会启动已配置的 blivechat 本机后台，不自动订阅直播间或开麦；不用时可关闭这个工具。启动失败不妨碍助播其他功能。配置页启动后一小时关闭，可再次双击配置入口打开。

接收端使用 Node 内置 WebSocket，固定接受 ws:// 明确回环地址和 /api/chat 路径，localhost 转为 127.0.0.1，拒绝外网地址、URL 用户信息和查询串，身份码不会发送到第三方代理。只发送加入房间和心跳，关闭自动翻译；依照作者 API 的 cmd=2 数组格式接受普通文字，忽略镜像跨房消息、礼物弹幕、表情图片、礼物与 SC，20 秒过期、去重和每秒 30 条入场限制沿用。最多五次重连，停用/旧连接迟到消息隔离；身份码拒绝或协议错误停止重试，不显示工具原始错误正文。

blivechat 版本依据：[作者使用说明](https://github.com/xfgryujk/blivechat#使用方法)、[v1.10.4 发布](https://github.com/xfgryujk/blivechat/releases/tag/v1.10.4)、[转发客户端](https://github.com/xfgryujk/blivechat/blob/848409df78d2cca65d3cc8ffe938eb6b6f261b76/frontend/src/api/chat/ChatClientRelay.js)、[消息序列化](https://github.com/xfgryujk/blivechat/blob/848409df78d2cca65d3cc8ffe938eb6b6f261b76/api/chat.py)。本机下载 SHA256 固定为 411f51518ebbfff31c9e37a432164c12fe11600c11bec7a1f1a95428e5620445，用于重放时核对同一下载产物，不等于作者签名。第三方运行包在忽略 data，不复制其源码进入本项目。

## 备用：自建官方应用

下面是原有官方适配流程。采用本机转发时无需准备这些开发者密钥；切回官方需在 .env 将 BILIBILI_SOURCE=official 并在空闲时重启助播。

## 先准备账号

1. 登录 [直播创作者服务中心](https://open-live.bilibili.com/open-manage)，查看开发者申请入口和要求。
2. 按实际审核要求申请资格，创建应用，确认应用具有对应直播间弹幕接入权限。
3. 在个人资料获取 Access Key ID、Access Key Secret，在项目中获取 App ID。
4. 在 [互动玩法首页](https://play-live.bilibili.com/) 获取自己的主播身份码。它不是房间号。

入口和凭据字段来自 [B 站官方示例](https://github.com/bilibili-openplatform/OpenLive_CSharpDemo)。账号能否通过审核、应用是否可用于当前场景，以平台实际页面和审核结果为准。不要把其他人的应用密钥、Cookie 或身份码用于本项目。

用户当前尚未申请开发者应用。本轮没有登录账号、提交申请或验证真实直播间连接。

## 本机配置与操作

在仓库根目录已忽略的 `.env` 中填写以下四项。不要将值发进聊天，不要填进 `.env.example`，不要提交到 Git。

```dotenv
BILIBILI_ACCESS_KEY_ID=
BILIBILI_ACCESS_KEY_SECRET=
BILIBILI_APP_ID=
BILIBILI_ANCHOR_CODE=
```

配置后需在本场收音和回复结束时重启助播后台。开发期间先备份聊天显示，使用 `scripts/start-cohost.ps1 -RoomSnapshot` 恢复，不直接覆盖或清空旧记录。

在 AIRI 设置 →“直播助播”找到“B站弹幕”，点击“连接 B站弹幕”。按钮先进入现有自动直播模式，然后连接 B 站。它不自动开麦。需要识别真人讲话时仍按原流程点击“开始收音”；小鲸鱼回复弹幕发声不要求开启麦克风，但需打开主窗口并让语音舞台就绪。

“已连接”仅表示长连接认证成功，不表示直播间有弹幕。让另一账号发送一句普通弹幕，确认气泡带“B站观众”标记，以及已接收数量增加。模拟观众输入仍标为“模拟弹幕”。昵称只用于显示，去重和同观众冷却使用平台 open_id。

小鲸鱼根据现场选择回应，不要求每条弹幕都回复。主播讲话、正在回答、暂停回应或冷却中时允许等待。断开 B 站只停止接收，新近已入队消息仍受原有 20 秒有效期约束；若想立刻停止助播，请用“停一下”或“暂停回应”。

未配置时连接按钮不可用。认证或平台权限失败会停止重试并显示简短原因，修好后手动重连。网络故障最多重试五次，等待时间依次为 1、2、4、8、16 秒；本次连接中累计达到第六次失败后停止。重启服务不会自动连接 B 站。

## 开发实现与边界

- `apps/cohost/bilibili.mjs`：固定官方 HTTPS API、HMAC-SHA256 签名、精确保留大整数 App ID、创建/结束应用场次、应用心跳与 WebSocket 心跳、认证、重连和取消。WebSocket 只接受官方域名的 WSS 地址。连接信息不返回给浏览器。
- 根据官方示例实现 `/v2/app/start`、`/v2/app/heartbeat`、`/v2/app/end`。结束的是当前应用场次，不是主播的直播。心跳每 20 秒，长连接认证超时 10 秒，无心跳回应超过 60 秒断开重试。
- 支持 16 字节包头、同消息多包、zlib 和 Brotli 压缩批次。限制解压总量、递归层数和包数。尚未通过真实 B 站数据验收，不把模拟协议测试当平台兼容保证。
- 仅处理 `LIVE_OPEN_PLATFORM_DM`，忽略礼物、付费留言和进房事件。核对房间，拒绝超过 20 秒的历史消息、异常未来时间与不合法内容。
- 优先用 `msg_id` 去重。旧官方格式缺少此字段时，使用房间、open_id、秒级时间和文本的摘要。该降级会将同观众同秒同文合并。延迟到达的弹幕不重置有效期。
- 入口每秒最多接纳 30 条合法弹幕进入队列，其余计入过滤数。队列 128 条、聊天显示 300 条。这个上限适合小规模试播，不保证大直播间每条消息均保留。
- 普通真实弹幕可进入导演候选，不强制点名。每批最多 16 条，弹幕判断至少间隔 3 秒。新背景弹幕不会取消当前弹幕判断，下一批再看。主播机会绕过弹幕判断间隔。原有回应全局 20 秒、同观众 60 秒冷却保持。
- 同一次模型调用选弹幕并拟稿，直接交给现有 TTS/Live2D 流程。没有增加第二个动作或回复模型。
- `/api/bilibili/status` 返回脱敏状态，`/api/bilibili/start` 和 `/stop` 仅允许本机、沿用访问令牌与来源验证。公开模拟入口不能伪造真实来源标记。
- 收到的弹幕按现有现场记录规则参与模型上下文。平台令牌和开发者密钥只用于 B 站连接，不进入模型提示或日志。

`tests/bilibili.test.mjs` 使用官方格式的模拟数据，验证签名、压缩批次、去重、限流、迟到、重连、取消、消息入场和主播优先。

`scripts/browser-bilibili-smoke.mjs` 使用独立模拟后端连接实际桌面和网页版。覆盖两端连接/断开、昵称和来源、重复弹幕只显示一次、普通弹幕自主回应、一次模型决定、窄屏布局。不读取用户旧聊天、不调用真实模型、不采集麦克风。

拿到应用权限后，进行自己的直播间短试播：普通问题、连续刷屏、主播讲述时来弹幕、明确交棒、网络断开再恢复。记录漏收、重复、错误插话与回应延迟。优先完成自然话轮验证，再考虑礼物答谢、欢迎和其他平台。
