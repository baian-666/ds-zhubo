# 后台任务归属与取消（2026-10-15）

本批收敛当前已有的任务，不新增模型调用、定时自主发言或通用插件执行器。输入、输出和后台整理各自保留状态；任务完成不代表语音已经播完。

## 已接入的范围

| 拥有者 | 工作 | 并发与等待 | 结果去向 |
| --- | --- | --- | --- |
| Participation | 自动参与判断和流式首句 | 一次当前判断；最多2个尚未退出的调用、1个排队项；默认4500ms总预算 | 原导演校验机会、角色、话题、静音和候选有效期；允许接话才交给输出话轮 |
| Director 的可选 semantic adapter | 旧的异步意图分类接口；生产默认未配置 | 同样最多2个调用、1个排队项；默认200ms | 仅当前 revision 可以提交意图，不绕过原有交棒规则 |
| SessionContinuity | 空闲时抽取原话摘要 | 1个执行项、1个等待项；重复输入合并；默认延后1秒并检查现场空闲 | 按来源 revision 更新派生摘要；不生成候选发言、不调用模型 |

统一原语在 [task-scope.mjs](../apps/cohost/task-scope.mjs)，仍是本地模块。各拥有者使用独立实例；没有把 ASR、LLM、TTS、播放和摘要塞进同一个 busy。已存在的语音、弹幕和播放队列保留专用协议及取消控制器。

## 生命周期与资源边界

- 状态为 waiting、running、completed、cancelled、failed；每个任务有 ID、拥有者、代次、创建/开始/结束时间及有限原因码。
- 同一个未完成 key 合并为同一任务。队列满时明确失败，不无限积压；记录最多保留24项，输入、台词、结果、密钥和上游异常正文不进入任务诊断。
- 父级取消、超时、清空或关闭都立即让等待方结束，并向执行器传递 AbortSignal。过期结果不得写回现场；若迟到结果带回复流，调用它的 close 清理。
- 取消不等于强制终止任意 JavaScript Promise。忽略 abort 的工作以及其迟到清理仍占物理槽位，诊断中显示 draining；槽位耗尽时停止追加，不假装资源已释放。CPU密集任务今后需要可终止 worker，不能在此调度器里同步跑推理。
- reset 先取消整代再调度，防止逐个清理时启动旧排队任务。close 幂等，关闭后提交新任务不会执行。任务队列不写入 SQLite；重启不会重做旧任务。
- 判断成功后，回复流的拥有者按“判断→候选→输出话轮”转交。已交接的流不会被旧判断的清理或计时器取消；后续仍由候选过期、话轮打断和流自身超时关闭。
- 摘要发布还检查来源 revision 与现场空闲。清空全部或某角色摘要会取消旧任务，迟到提取不得把删除内容带回来。维护失败保留旧摘要；等待超过5分钟或失败后不反复自动重试，新的现场输入可再次调度。

## 服务关闭与保留的通道

服务现在在调用 server.close 时先取消生产者、关闭状态订阅、释放输入/输出和维护任务，再等待连接退出；不再等最后一个长连接断开才开始清理。HTTP异步操作同时受请求断开和服务生命周期约束，声音配置的迟到校验不能在关闭后保存。

ASR收音代次、TTS合成队列、播放回执、表演时钟继续使用原有链路。关闭侧栏、切设置、关麦不触发整个后端任务作用域关闭；这些现有行为由媒体回归验证。共享 Index/Aqua 进程独立于单场会话，不因后台任务取消而被停止；本批未改它们的启动或合成实现。

新增只读鉴权 GET `/api/tasks`，按 participation / semantic / maintenance 返回当前任务和有限历史。诊断按需读取，未加入200ms状态广播或新的前端轮询。它不是面向模型的工具，也不能直接启动任务。
