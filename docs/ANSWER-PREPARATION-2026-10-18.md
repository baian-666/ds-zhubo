# 完整回答延迟：静默准备与连接维护

2026-10-18。接续[上一轮延迟优化](ANSWER-LATENCY-2026-10-18.md)。本轮使用原合成猫咪故事、附和／接管及恢复讲话素材，用户已授权原百炼 FunASR/Qwen 与 DeepSeek 服务。没有替换声音或对话模型。

**发布决策：完整回答静默准备保留为实验，默认关闭，不把4.09秒样本当作可靠发布证明。准备路径的长回答出现一次生成失败；附和还出现11ms／308ms误暂停，未满足用户要求。已交付版本只启用收听时连接维护，原四字短反应、普通回答和话轮判据保留。** 实验通过构造参数 `answerPreparationEnabled:true` 显式启用；实际试验脚本用 `--no-answer-preparation` 测默认发布行为，避免下次正常启动意外启用实验。

## 实现

- 把准备和发声许可分开：持续停顿约650ms、当前文字稳定至少300ms后，静默准备完整回答及首句音频。必须等最终转写一致、原导演确认话轮结束，才能转为普通回答。只忽略末尾标点差异，不忽略内部标点、数字、否定或文字修正。
- 准备覆盖所有尚未交付的识别段，按前端相同顺序拼接。前一段结果未到齐时不猜上下文。最多保留8段，前端确认交付或停止收音后清理。
- 继续讲话、识别内容改变、切角色／声音／话题、停止或静音都会作废准备。每识别段最多6次尝试，模型任务4.5秒上限，未接手音频8秒准备上限；完整首句缓存最多6MB，短反应仍为1MB。接手后改由普通语音45秒请求期限负责，不能因早期准备的8秒限制截断长句。不建立新聊天、不执行表演、不提前写已说记忆。
- 长停顿后，未播的四字短反应及其判断让位于完整回答准备。已经在播的短反应不因此停止；完整回答仍用原640ms不明语音暂停、1800ms取消和附和许可。没有缩短这些打断阈值。
- 明确叫“小鲸鱼”的直接回答和普通参与回答都复用同一份准备结果。首句已到的PCM立即转交，后续PCM继续流式输出，不等整句合成完成。后续句子照常合成；准备失败时不把空音频标成播完。
- 静默准备按讲话的时间顺序理解合并转写：前文要求先听、后文已讲完并明确邀请回答时，以后来的交棒为准。最后仍要求先听、引用中的问句或未交棒仍等。此指导只用于静默准备，不改正在播放时的接管判据。
- 再明确草稿任务不负责实时开口判断：临时标识、最终标点或尚在收音不能单独成为wait理由，不让模型猜测呼吸；文字问题完整便可准备。缺少对象／依赖后半句／当前仍要求先听继续wait，真正播放依旧受最终原文与程序话轮许可约束。
- 只在实际收听、搭档讲话且没有语音播放时补齐Qwen连接。20秒闲置作为提前准备替换连接的本机策略，不是宣称供应商超时恰为20秒。旧的健康连接在替换就绪前继续可用；补齐不借走现有可用连接。每次最多2条、失败后至少5秒再试、12秒超时，关麦取消维护，不在后台长期循环合成。

## 资料与边界

[LiveKit官方提前生成选项](https://docs.livekit.io/reference/agents/turn-handling-options/)把提前LLM/TTS与最终话轮确认分开，也要求限制重试。这里按现有AIRI架构实现同样的所有权边界，没有引入新平台。
[FunASR官方客户端事件](https://www.alibabacloud.com/help/en/model-studio/fun-asr-client-events)区分任务结束和分句静音阈值。本轮保留最终任务确认，不把临时分句直接冒充完整用户输入。

识别尾延迟、模型首句和合成仍有真实耗时；准备不命中会回到原流程。更广泛真人长聊、外放回声、误停率及延迟分位数仍未验收。
